# 快照与上传缓存的磁盘保护

状态：实施。目标是避免导出异常、上传失败和大工作区导致用户磁盘持续增长；不修改用户 index、HEAD 或分支，不改上传协议，不修复 SSH 下游服务或生产存量数据。

## 设计

- 共享 `spool-storage.js` 管理默认限额、真实文件统计、生产互斥、过期临时文件和缓存回收，安装到 Claude 与 Codex 脚本目录。
- 默认缓存软限额/回收目标 256MiB、硬限额 512MiB、最少剩余空间 1GiB。统计 raw（包括旧 bundle.lock、新临时文件及未知普通文件）、sent、discarded 和上传器状态；不跟随符号链接。
- uploader 在无上传 URL 时也运行清理。优先清理过期临时文件和已上传文件；硬限额或低空间时才按时间回收稳定的待上传文件，逐个重查剩余空间，保留新写入和仍活跃的临时文件。记录丢弃原因。未知文件计量但不自动删除。
- producer 在写 Git 对象之前预检改动文件，默认单文件 8MiB、总量 32MiB、最多 1000 个路径；超限明确跳过整帧，不冒充完整快照。临时 index 必须在 add/read-tree 成功后才使用。
- 同一 spool 同时只有一个快照生产者。生产前预留 bundle 上限的配额和空闲空间；无空间则只上报跳过原因，不生成快照对象。
- `git bundle create -` 通过 stdout 流式写入 PID 标识临时文件，最多 32MiB；超限/超时/失败关闭管道并删除临时文件。Git 子进程不持有磁盘输出文件，因此杀掉父进程不会留下继续增长的 bundle.lock。正常退出并校验后原子改名为原有文件名。
- 隐藏 refs 只在已有上传成功证据且超过 7 天时回收；达到本仓库 256 个 refs 后若不能安全回收，停止新对象生产。保留当前会话的最后一帧及派生序号，不执行 gc/prune。
- 本轮保留每次事件独立 bundle 的协议与关联方式，不通过复用旧 bundle 引入新的下游恢复契约。

## 验证、风险与发布

使用真实临时 Git 仓库验证限额、SSH remote、bundle 恢复、初始仓库、用户 index/HEAD 不变；使用临时 spool 验证旧锁、新活跃临时文件、sent 优先、低空间停止、未知文件、无 URL 清理、上传确认与状态裁剪。所有测试使用小限额，无需创建 GB 文件。

Native Claude raw body 由外部进程写入，缓存硬限额是周期清理阈值，无法阻止两次运行之间的外部写入；生产者自身可以在写入前和流式写入期间限制体积。低空间和超额策略可能丢弃最旧待上传制品，必须记录并在文档中说明。无法读取剩余空间的旧 Node 仍执行缓存容量限制；新版 Node 可额外执行 free-space 保护。

发布需先完成本地测试、打包内容核验，再由用户验收决定发布。用户运行新版安装器后生效；不在本次开发中修改真实用户的缓存或配置。回滚恢复旧脚本和 endpoint 配置，但将重新暴露旧漏洞；不自动恢复已过保留期而删除的数据。
